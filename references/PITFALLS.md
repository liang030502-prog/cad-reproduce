# 实测坑清单

全部条目都是在本机实测出来的，不是推测。括号里是对应的实测数字。

---

## 一、AutoCAD 无头调用（`accad.py`）

### 1. 退出码完全不可信
脚本文件不存在也**返回 0 且无任何输出**；关键字写错**不报错，而是 100% CPU 死循环**
（实测 SAVEAS 版本号写 `2099` 挂 >90s，`-PLOT` 设备名错挂 >60s 且不断重问同一提示）。

→ 必须四重判定：**超时 + 杀进程树 + 输出文件体积下限 + 脚本自打印标记**。

### 2. 重定向 stdout 是 UTF-16LE
按 UTF-8 解码会得到字符之间夹空字节的乱码，标记字符串找不到。

### 3. `.scr` 必须是 ANSI(GBK) 编码
同一份内容写成 UTF-8 **会挂起**，不是报错。

### 4. 不能用管道接 stdout
accoreconsole 的子进程继承管道句柄，**超时后读取会二次阻塞**，比原超时更难脱身。
重定向到文件即可。

### 5. 脚本末尾不要写 `QUIT`
会被追问"确实要放弃对图形所做的全部修改吗"，应答没排队就永久等待。
实测这一条让一次**已经成功出图**（PDF 已落盘 143KB）的运行白等 3 分钟超时；
去掉后同一操作 **4.2 秒**完成。

### 6. `-PLOT` 会挂起，`-EXPORT` 不会
`-PLOT` 的应答是**位置参数**且**一次答错就永久重问**。`-EXPORT` 只问 5 个
（格式/出图区域/详细配置/文件名/结束），稳得多。

### 7. `-EXPORT` 会按视口裁切
实测把 249×176mm 的内容导到 A3 纸上仍被裁边，且**图框不进导出**。
→ 所以它适合判字体/填充/线宽，**不适合做全幅像素比对**。

### 8. `/l en-US` 会挂起
本机是简体中文，无英文语言包。用 `/l zh-CN` 或干脆不带 `/l`。

### 9. 不要用生成的 `.bat` 包一层
cmd 按 OEM 代码页解码 `.bat`，含中文路径的 GBK 批处理会以 9009 退出。

## 二、ezdxf / DXF

### 10. 字体用**家族名**，不是文件名
`find_best_match("SimSun")` → `simsun.ttc`；传 `"simsun.ttc"` **解析失败并静默回退
`arial.ttf`**（无中文字形 → 中文变豆腐块）。
→ 本流程在 `build` 里加了硬失败守卫，解析不了直接报错退出。

### 11. `ezdxf.new(setup=True)` 是坑
会建 26 个指向 `OpenSans-*.ttf` / `Liberation*.ttf` 的样式，AutoCAD 里没有这些文件，
日志会刷屏 `[simplex.shx] ← [OpenSans-Light.ttf]` 全部替换。**用 `setup=False`。**

### 12. `add_linear_dim` 返回的是 `DimStyleOverride` 包装，不是实体
实体在 `.dimension`，setter 在包装上。写 `dim.dxf.text` 会 `AttributeError`。
`text="<>"` **本来就是默认值**（关联标注）。

### 13. `render()` 必须调用
否则 DIMENSION 实体存在但**没有几何块**，图纸上什么都看不见。

### 14. `p1`/`p2` 必须是"**被标注特征上的点**"
不是尺寸线的端点。传错会让 CAD 测量**偏移距离**——
实测一个 30mm 的标注渲染成 `4,1`（正好是 4.1mm 的偏移量）。

### 15. ACI 7 **不是黑**
它是"黑或白，哪个与背景对比度大用哪个"，在 AutoCAD 深色模型空间里显示为**白色**。
纯黑用 **ACI 250**。（附带：ACI 250–254 与 7 在某些语境下表现不同，别互相替代。）

### 16. 闭合 LWPOLYLINE **不填充**
要实心必须 `HATCH` + `set_solid_fill()`。而且 `$FILLMODE` 必须为 1，
否则屏幕显示空心（打印仍是实心），容易误判。

### 17. 两个不同的 `finalize` 陷阱
`Frontend(...).draw_layout(..., finalize=True)` 会按等比坐标**改掉图框尺寸**
（实测 9.975×7.093in 被改成 6.75×4.8in），像素网格就废了。
→ 用 `finalize=False` 并自己设 `set_size_inches` / `set_position` / `set_xlim`。

### 18. BYLAYER 在渲染器里解析成 `#ffffff`
白底上默认颜色的几何**全部不可见**。要么显式给颜色，要么改 `ColorPolicy`。

### 19. `FontManager` 没有 `set_fallback`
回退字体名是私有状态，只能校验不能设置（ezdxf 1.4.4）。

## 三、几何与配色语义（本项目特有）

### 20. **一条 PDF path 不是"一个形状"**
图框和无关线段可能共处同一条 path。用 path 的外接矩形判断"是否落在某区域内"，
会把整条 path 删掉——实测因此**丢了整个图框（占黑墨水 81%）**。
→ **逐图元判断**，只删真正落在区域内的 item。

### 21. 尺寸抑制区必须**做薄**
用整条尺寸线的外接矩形当抑制区，顶部尺寸链横跨 171→315pt，
那块矩形把上半张图的图框一起吃了。
→ 按方向做**带**：横向标注只在垂直方向留 3pt 宽。

### 22. "笔宽吞没"判据必须要求**形状成立**
只比较"半宽 ≤ 笔宽"，会把 2369 条 0.12–0.84pt 的**退化碎片**
（线端、虚线段帽、剖面线小面）误判为实心，生成一堆无用 HATCH。
→ 加"≥3 个顶点、两个方向都有面积"后 2289 → 210，真正的 102 个实心点全部保留。

### 23. 实心点半径要**加半个笔宽**
源图是"小圆 + 更宽的笔"，落纸尺寸 = 几何半径 + 笔宽/2。
只按几何半径画会得到 2/3 大小（实测 1.2–2.6pt vs 源图 2.4pt）。

### 24. 不可见文本层
有些 PDF 的尺寸数字文本层是 `3 Tr`（**不可见**），可见的数字其实是**字形轮廓**。
→ 必须"删轮廓 + 补真 TEXT"，只做一半会导致数字消失或重复。
**数字的颜色要取轮廓的颜色，不是文本 span 的颜色。**

### 25. 一个标签只能归一个标注
用"标签在附近就归它"，会让同一个数字被十几个尺寸共用（实测 694.8 出现在 11 个跨度上）。
→ 取**最近的那一个**。

### 26. 界线方向取**远离尺寸线的那一端**
界线从特征延伸到尺寸线（并略过一点），所以特征端是**离尺寸线最远**的那端。
取反会把每个标注镜像到错误一侧。

### 27. 颜色角色可能与直觉相反
本图纸实测：**红 = 中心线**，**绿 = 尺寸线与界线**，黄 = 说明文字，青 = 剖面线，
品红 = 特殊标记，黑 = 零件轮廓。**先量再写规则**，别假设红就是尺寸线。

## 四、验证用的"尺子"本身（最容易犯错的地方）

### 28. ezdxf 的 matplotlib 渲染器**不按毫米画线宽**
实测 0.18/0.25mm → 1px，0.50mm → 2px，1.00mm → 4px（应为 2.1/3.0/5.9/11.8px）。
→ **绝不能用它判定线宽**，否则会把线太细误报成几何缺陷。

### 29. 它的 CJK 字体解析不可靠
同一份 DXF，该渲染器把中文画成**空方块**，而 AutoCAD 出的 PDF 字体是 `SimSun`、
719 字符、中文完全正常。→ 中文字形只能看 AutoCAD 出图。

### 30. 不要用"墨水面积"当门禁
两种光栅化器的抗锯齿范围不同，源图恒定多约 25%（实测）。
→ 面积指标会**误杀正确图纸**，比没有门禁更糟。用"带内一致率"。

### 31. 容差带要用**毫米**不要用像素
像素带在 150dpi 合适、300dpi 就无法通过，门禁结论会随分辨率漂移。

### 32. 两个渲染器不能直接比
拿 MuPDF 的语义去比 ezdxf 的语义，量出来的大部分是**两个渲染器的口径差**。
实测同一张图：库渲染器给 0.7866，自建 tracer 给 **0.9774**。
→ **必须用同一个光栅化器跑两遍**（源几何一遍、成品一遍）。

### 33. tracer 忘画 DIMENSION 对应的几何
第一版 tracer 没画尺寸线/界线/箭头，于是把 13923 个绿色像素报成
"源图有、成品没有"，看着像巨大几何缺陷，其实是**尺子少画了一样东西**。
（补上后未匹配像素 17233 → 8455。）

### 34. 容差带收敛曲线要看**是否封顶**
若加宽带子后一致率**封顶**，说明剩下的是真实结构差异而非线宽。
实测：0.12mm→0.7866，0.20mm→0.8874，0.30mm→0.9261，0.45mm→0.9323（旧尺子，封顶 ~0.93）。
换新尺子后 1px 带就到 0.9774。

## 五、环境

### 35. AutoCAD 可能不在 C 盘
本机装在 `D:\AutoCAD 2021`。**必须查注册表**：
`HKLM\SOFTWARE\Autodesk\AutoCAD\R24.0\ACAD-4101:804`。
只搜 `C:\Program Files\Autodesk` 会误判为"未安装"。

### 36. 工作目录可能不可写，且与文件沙箱无关
文件沙箱策略再宽，也**管不了 Windows ACL**。实测某目录属主是 Administrators、
当前账户只有读权限，于是每条 shell 命令都失败（DSH 想授权却无权改 ACL）。
→ 用提权 `icacls "<dir>" /grant "<user>:(OI)(CI)M" /T /C` 授予，或换目录。

### 37. `pdf_to_dxf` 类"直接转换"不如复刻
源 PDF 的矢量是**打印机的**矢量：充斥着 0.12pt 碎线段、描边宽于形状的小圆、
不可见文本层。直接转出来的 DXF 又碎又不对。
**必须按语义重建**（合并共线、识别实心、重建文字）。
